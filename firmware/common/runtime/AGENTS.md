# Shared ESP32-S3 runtime services

Opt-in ESP-IDF component for NVS device configuration and bounded diagnostic logging. Board adapters choose display capability and optional diagnostic console sink. Keep controller initialization, radios, storage and pins outside this board-neutral component.

- Preserve the `oscfg` NVS namespace, credential/PIN/token secrecy and explicit settings validation. One command worker writes settings; readers use the guarded snapshot.
- Every save writes the complete configuration as one versioned `cfg` blob with a CRC-32, one `nvs_set_blob` and one commit, then reads it back. NVS replaces a blob entry as a unit, and the CRC rejects a damaged record. A missing or invalid `cfg` falls back to the legacy per-key layout, which is read for migration and never erased or rewritten. A blob value passes the same validation as a legacy key. No hardware power-cut test proves this yet, so report persistence failures and do not claim measured power-cut durability.
- Configure the borrowed diagnostic callback sink before tasks start; it must outlive the log ring. Secret values are never added to CONFIG JSON or diagnostic logs.
- `opensensor::log::attach_persistent()` moves the log onto a no-init PSRAM ring with disconnect events and counters when the image sets `CONFIG_SPIRAM_ALLOW_NOINIT_SEG_EXTERNAL_MEMORY` and PSRAM initialized. Otherwise the 4 KiB internal ring stays. Ring bytes and event slots come from `CONFIG_OS_LOG_PERSIST_RING_BYTES` and `CONFIG_OS_LOG_PERSIST_EVENT_SLOTS` (defaults 64 KiB and 64), so a board shrinks them in its `sdkconfig.defaults`. A runtime layout passed to `attach_persistent(layout)` must fit that reservation. Reads copy at most `DebugLog::kLockedCopyBytes` or 16 events per critical section, and writers keep the spinlock so they stay ISR safe. Never fail a build or boot for lack of PSRAM, and never select the path by board name. Keep the header layout (`DebugLog::Header`, 112 bytes) stable or bump its version. ESP-IDF PSRAM init writes a probe word to PSRAM physical address 0 on every boot, so the block keeps a 64-byte guard in front of it. PSRAM sits behind the write-back data cache, so every persistent write is written back through the `attach` writeback hook. Without either, a reset loses the header (both measured on CoreS3, 2026-10-11).
- `opensensor::log::report_coredump()` runs once after `nvs_flash_init()`. For a saved core dump that no earlier boot reported it writes one `COREDUMP present=1 valid=... bytes=... sha=... task=... pc=... exc_cause=... exc_vaddr=... elf=... prior=... saved=...` line, then stores the dump's size and stored SHA-256 as a 37 byte blob in NVS namespace `osdump`, key `reported`. Never erase the dump from firmware, `coredump-info` must still read it. When the record cannot be read the dump is reported again, never hidden. The decision and line live in the pure `coredump_report.h` behind borrowed callbacks, and `pixi run coredump-report-test` runs it with fake flash and NVS. Keep task names and hashes as the only text in the line, nothing from settings or secrets.
- `opensensor::power::configure_dfs()` enables dynamic frequency scaling between `CONFIG_OS_PM_DFS_MIN_MHZ` and `CONFIG_OS_PM_DFS_MAX_MHZ` with light sleep off, only when the board sets `CONFIG_PM_ENABLE`. It logs one `POWER DFS` line. Components that need full speed hold their own `esp_pm` lock.
- Configuration and log tests compile the real implementation against host SDK fakes. They establish logic and failure handling, not hardware NVS or power-loss durability.

Use the pinned native ESP-IDF environment. Before changing SDK/dependencies,
check current official documentation/latest stable versions and record exact
pins plus compatibility evidence. Never add Arduino Preferences, Print or APIs.

- Location normalizes after the complete patch using official H3; store only the published cell with its maximum resolution and owner-declared assigned ISO country. Increasing precision cannot upsample stored cells. Missing records use defaults; malformed stored location is unset and malformed NTP is disabled. Secrets remain absent from all configuration pages.
