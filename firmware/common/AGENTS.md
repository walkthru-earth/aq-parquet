# Shared firmware code

This directory holds reusable modules across ESP32-S3 board trials. The base `AQCommon` component in `src/` has no board pins, M5Unified calls, card mount policy, RTC driver, power, display, modem or radio initialization. The opt-in `runtime/` component holds settings/logging under its own AGENTS.md. The opt-in `connectivity/` component owns BLE/Wi-Fi transports under its own AGENTS.md. The opt-in `logger/` component owns the sampling deadline and single archive worker under its own AGENTS.md. The opt-in `location/` component owns official H3 geometry/validation under its own AGENTS.md. The board trial owns hardware adapters, mounting policy, its measurement schema/version and acquisition/optional RTC callbacks.

- Keep the Plantower byte framing and checksum here. Choose the sensor model explicitly at construction: PMSA003 and PMS5003T have the same 32-byte envelope, but different meanings at bytes 24–27. Never publish the PMS5003T's temperature/RH words as >5/>10 µm particle counts.
- Keep the bounded Parquet writer and LZ4 adapter here. Preserve `vendor/lz4` bytes and license; the adapter is tested with sanitizers and two readers via `pixi run parquet-test --sanitize`.
- A trial adds the common component directories through CMake `EXTRA_COMPONENT_DIRS` and declares `REQUIRES common runtime connectivity logger` as needed. Native ESP-IDF 6.1 is the target; do not introduce Arduino components or APIs. Never include a sibling trial. New board trials pass their own `created_by` to the writer; the default is the historical CoreS3 identity. Schema identifiers and provenance remain trial-owned; do not change existing file identities as a side effect of a repository rename.
- Numeric rows, UTC arithmetic and sync wire/path/checksum helpers are pure C++ and tested on the host. AQLogger owns clock locking and absent-safe runtime field mapping; board acquisition and RTC callbacks run only on its main-loop path. Never invent an anchor or silently rewrite old rows.
- Device settings retain their NVS namespace and security behavior. `DebugLog` uses the native `LogOutput` interface and can borrow a board-selected function/context console sink, set before tasks start. Shared sensor register drivers borrow IO/timing callbacks and never initialize the controller.
- Shared STATUS/LIVE JSON is bounded to 480 bytes; BLE response frames remain at most 512 bytes. Preserve the board-specific LIVE temperature semantics and no-RTC/null-UTC behavior. Physical UART owner/provisioning replies bypass DebugLog; never expose PIN/PSK/profile output through LOG_TAIL, radio responses or retained captures.
- Board-specific validation belongs in that trial's README and its board's docs. A host fixture is not a real SD or power-loss test.

- Router DHCP option 42 and configured local time servers precede permitted public fallback. Successful responses alone establish network UTC. Persist only the privacy-coarsened H3 cell, cap and optional owner-declared country; capture per sample and split files on changes. GET_CONFIG page 0 remains legacy-compatible; additive pages retain framing limits.
